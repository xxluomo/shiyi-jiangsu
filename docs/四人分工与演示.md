# 四人分工与演示建议

以下是建议的模块责任，不代表已经发生的个人贡献。正式报告需要按组员实际完成的工作填写。

| 成员 | 模块责任 | 建议掌握和演示的内容 |
| --- | --- | --- |
| 1 | 数字展厅、首页、详情与素材整理 | CSS响应式、检索条件、图文组织、图片缩放、多图、来源 |
| 2 | 剪纸和蓝印工坊、作品导出与保存 | Canvas坐标变换、对称旋转、平铺参数、操作栈、PNG、作品接口 |
| 3 | 地图图谱、学习流程、音频与答题 | GeoJSON到SVG、关系布局、Audio/Range、题目快照、评分与学习进度 |
| 4 | 用户权限、后台、数据库与部署 | 表结构迁移、角色/所有权、CRUD、媒体解码、统计图、启停与测试 |

每位成员都应实际修改、验证自己的模块，整理约3项文化内容或相关素材，并撰写对应报告部分。接口和数据库设计由全组共同讨论，最后共同联调。

## 建议演示顺序（8—10分钟）

1. 首页说明江苏主题，展示12项馆藏、6个城市和4个专题。
2. 在展厅按南京或材料关键词检索，进入详情、切图和放大。
3. 切换地图城市、图谱节点，说明它们读取同一份馆藏数据。
4. 使用student/123456登录，收藏项目、完成工艺学习。
5. 在剪纸画布实际画一笔，撤销重做；切蓝印调整参数，保存作品与导出PNG。
6. 播放导览、展开文字稿，完成5题挑战，查看错题解析。
7. 在个人中心展示收藏、作品、答题与学习记录。
8. 退出普通账号，使用admin/123456登录后台，查看真实统计图、项目草稿与题库维护。
9. 编辑一处项目简介并保存，回到前台刷新验证；演示前可先备份data。

## 每个人都应能解释的问题

- 前端在哪里发HTTP请求，后端在哪里处理，数据最终写到哪里？
- 哪些是生成插画或示意，哪些是整理自官方资料，音频是谁的声音？
- 为什么普通用户不能使用管理接口或删除别人的作品？
- 为什么改题库不会影响已经开始的答题？
- 网站关闭重开，哪些数据保留？哪些临时画布操作不会保留？
- 地图和图谱的连线分别表达什么，为什么不能宣称未做过的AI推断？
